## 1. Вступ
### 1.1 Призначення
Документ визначає функціональні, інтерфейсні, бізнес-логічні та нефункціональні вимоги до системи управління персоналом «Персонал+» і є основою для тест-кейсів, автоматизації перевірок та приймання продукту.

### 1.2 Обсяг
Охоплено модулі поточної версії: вхід, Admin (користувачі), PIM (працівники), Leave (відпустки), Time (табелі), Recruitment (вакансії, кандидати), My Info, а також Java-модуль бізнес-логіки (відпустки, нарахування, перевірка даних працівника). Модулі Performance, Directory, Maintenance, Claim і Buzz у версії 1.0 не специфікуються.

### 1.3 Терміни і скорочення
- **HRM**: Система управління персоналом (Human Resource Management).
- **PIM**: Модуль обліку працівників (Personal Information Management).
- **ESS**: Самообслуговування працівника (Employee Self Service).
- **Табельний номер (Employee Id)**: Унікальний ідентифікатор працівника; призначається під час додавання.
- **Ліміт відпустки (entitlement)**: Дні відпустки певного типу, призначені працівникові на період відпусток.
- **Баланс відпустки**: Ліміт мінус використані, заплановані дні та дні у заявках, що очікують погодження.
- **Табель (timesheet)**: Тижневий облік годин за проєктами і видами робіт.
- **РНОКПП**: Реєстраційний номер облікової картки платника податків (10 цифр).
- **Часткові дні (Partial Days)**: Поділ робочого дня відпустки на частини (пів дня / 0.5 дня).

## 2. Загальний опис
### 2.1 Користувачі та ролі
У поточній версії ролі «Керівник підрозділу» і «HR-менеджер» реалізовані через роль користувача Admin, «Працівник» через ESS. Тестовий обліковий запис адміністратора: Admin / admin123. До прав ролей HR-менеджер та Адміністратор віднесено нарахування заробітної плати, податків та компенсацій (Payroll).

### 2.2 Середовище
Вебзастосунок; клієнт — актуальні версії Chrome або Firefox, роздільна здатність не менше 1280×720. Поточна версія розгорнута за адресою (маршрут входу `/web/index.php/auth/login`). Інтерфейс поточної версії англомовний: назви елементів і статусів наведено так, як на екрані. Формат дат у полях і в підказці поля дати — yyyy-MM-dd (Рік-Місяць-День).

### 2.3 Обмеження і припущення
- Дані демо-стенду періодично скидаються; створені записи не зберігаються між сеансами тестування.
- У версії 1.0 немає інтеграцій із зовнішніми сервісами (державні реєстри, портали вакансій) і мобільного застосунку.
- Модуль бізнес-логіки — окремий Java-проєкт (JDK 17, Maven) без графічного інтерфейсу; його правила перевіряються юніт-тестами.
- Ставки податків і норми чинні для 2026 року.

## 5. Вимоги до бізнес-логіки модуля
Модуль Java 17, пакет `ua.kpi.tzyapz.personal`, класи `LeaveCalculator`, `PayrollCalculator`, `EmployeeValidator`. Дати `java.time.LocalDate`; суми у гривнях, `java.math.BigDecimal`, округлення `HALF_UP` до 2 знаків (копійок). Некоректні аргументи (від'ємні значення, відсутні дати) — `IllegalArgumentException`.

Параметри модуля (публічні константи класів): `ACCRUAL_PER_MONTH = 2` дні, `MAX_ACCRUAL_PER_YEAR = 24` дні, `MAX_CARRY_OVER = 5` днів (BL-10, BL-20); ставка ПДФО `PIT_RATE = 18%`, ставка військового збору `MILITARY_RATE = 5%` (BL-50); `HOURS_PER_MONTH = 168`, `OVERTIME_COEF = 1,5` (BL-60, BL-70); `MIN_AGE_YEARS = 16`, `TAX_ID_LENGTH = 10` (BL-80).

| ID | Формулювання | Пріоритет |
| :--- | :--- | :--- |
| **BL-10** | `LeaveCalculator.accrued(monthsWorked)`: за кожен повний відпрацьований місяць нараховується 2 дні; за рік не більше 24, тобто accrued = min(2 × monthsWorked, 24); якщо `monthsWorked < 0` — викидати `IllegalArgumentException`. Приклади: 5 → 10; 13 → 24. | High |
| **BL-20** | `LeaveCalculator.carryOver(unused)`: на наступний рік переноситься min(unused, 5) днів; якщо `unused < 0` — викидати `IllegalArgumentException`. Приклади: 3 → 3; 9 → 5. | Medium |
| **BL-30** | `LeaveCalculator.durationDays(start, end)`: кількість календарних днів у проміжку включно з обома датами (мінус офіційні державні свята). Якщо `start` пізніша за `end` або дата відсутня — викидати `IllegalArgumentException`. Приклади: пн 07.09.2026 — пт 11.09.2026 → 5; 09.09 — 09.09 → 1. | High |
| **BL-40** | `LeaveCalculator.canRequest(balance, duration)`: true лише якщо `duration >= 1` і `duration <= balance`; інакше false. Якщо `balance < 0` або `duration < 0` — викидати `IllegalArgumentException`. Приклади: (5, 5) → true; (5, 6) → false; (5, 0) → false. | High |
| **BL-50** | `PayrollCalculator.net(gross)`: сума «на руки» = gross - gross × PIT_RATE - gross × MILITARY_RATE з округленням `HALF_UP` до копійок. Метод обробляє значення gross у діапазоні від 0.01 до 1 000 000.00 грн включно; якщо `gross` поза цим діапазоном або відсутній — викидати `IllegalArgumentException`. | **BL-80** | `EmployeeValidator`: `isValidEmail(email)` — формат «локальна@домен.зона»; `isValidTaxId(taxId)` — рівно 10 цифр без інших символів; `isHireDateValid(hireDate, today)` — дата найму не пізніше за поточну; `isOldEnough(birthDate, hireDate)` — на дату найму виповнилося не менше 16 повних років. `validate(email, taxId, birthDate, hireDate, today)` повертає список кодів помилок `EMAIL`, `TAX_ID`, `HIRE_DATE`, `AGE` (порожній — дані коректні); у разі передачі `null` замість email або taxId метод додає відповідні коди помилок; відсутня обов'язкова дата — `IllegalArgumentException`. | High |
